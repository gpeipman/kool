IDisposable interface¶

Seni oleme programmides kasutanud andmeid, mis elavad mälus — muutujaid, massiive ja loendeid. Aga mõned asjad programmi elus on sellised, mida tuleb pärast kasutamist käsitsi kinni panna. Näiteks avatud fail, võrguühendus või andmebaasiühendus hoiavad enda taga ressursse, mida arvuti operatsioonisüsteem peab haldama.

Kui need ressursid jäävad lõpuni vabastamata, tekivad probleemid: fail jääb lukku ega ole teistele programmidele avatav, ühendusi koguneb ülearu ja programm muutub aeglaseks.

Selles peatükis vaatame, kuidas C#-s selliseid ressursse õigesti vabastada.

Mälu ja ressursid on erinevad asjad

C#-is korjab mälus olevad kasutud objektid kokku prügikoguja (garbage collector) meie eest. Aga prügikoguja ei tea faililukust, võrguühendusest ega muust välisest ressursist — need tuleb ise vabastada. Just selleks on IDisposable.

Mis on IDisposable?¶

IDisposable on liides (interface) nimeruumist System. Liides on omamoodi leping: kui klass selle endale võtab, peab ta selle lepingu tingimused täitma.

IDisposable-liidesel on täpselt üks meetod:

public interface IDisposable
{
    void Dispose();
}

Lühidalt: klass, mis haldab mingit välisressurssi, ütleb IDisposable liidese abil: "Mina oskan enda ressursse vabastada — kutsu lihtsalt meetodit Dispose()."

Klass, mis vajab ressurside vabastamist¶

Vaatame lihtsat näidet klassist, mis esindab ühendust. Ühenduse "avamisega" eraldatakse ressursse ja seetõttu peab see klass pakkuma meetodit Dispose():

public class Connection : IDisposable
{
    public Connect()
    {
        Console.WriteLine("Ühendus avatud.");
    }

    public void Send(string sõnum)
    {
        Console.WriteLine("Saadan: " + sõnum);
    }

    public void Dispose()
    {
        Console.WriteLine("Ühendus suletud.");
    }
}

Pööra tähelepanu paarile asjale:

  • : IDisposable tähendab, et klass kasutab IDisposable liidest.
  • Dispose() on meetod, mis vabastab ressursi. Kui IDisposaleble liidest kasutame, siis peab Dispose() meetod olemas olema — muidu kood ei kompileeru.
  • Klass oma töö käigus küsis mingi ressursi ja Dispose() vabastab selle.

Dispose() käsitsi kutsumine¶

Lihtsaim (aga veaohtlik) viis on luua objekt, kasutada seda ja lõpuks kutsuda Dispose():

var u = new Connection();
u.Send("Tere!");
u.Dispose();

See töötab, kuid sellel on üks suur puudus — kui objekti kasutamisel tekib viga, siis Dispose() meetodit ei kutsuta ja ressurss jääbki vabastamata. Just selle probleemi lahendab using-klausel.

using-klausel¶

using-klausel on spetsiaalne plokk, mis kutsub Dispose() meetodi automaatselt välja ploki lõpus — ka siis, kui ploki sees tekib viga.

using (Connection u = new Connection())
{
    u.Send("Tere!");
    u.Send("Kuidas läheb?");
}
// siin on Dispose() juba automaatselt kutsutud

using System;

namespace DisposeApp
{
    public class Connection : IDisposable
    {
        public Connect()
        {
            Console.WriteLine("Ühendus avatud.");
        }

        public void Send(string sõnum)
        {
            Console.WriteLine("Saadan: " + sõnum);
        }

        public void Dispose()
        {
            Console.WriteLine("Ühendus suletud.");
        }
    }

    class Program
    {
        static void Main(string[] args)
        {
            using (var u = new Connection())
            {
                u.Send("Tere!");
                u.Send("Kuidas läheb?");
            }
        }
    }
}

Programmi väljund on järgmine:

Ühendus avatud.
Saadan: Tere!
Saadan: Kuidas läheb?
Ühendus suletud.

Näed, et Dispose() kutsuti ise välja kohe, kui using-plokk lõppes. Me ei pidanud seda käsitsi kirjutama.

Lühivorm: using-deklaratsioon¶

Uuemates C# versioonides (alates C# 8.0) on olemas ka lühem vorm, kus using-plokki ega sulge pole vaja. Objekt vabastatakse siis, kui programmi osa, kus see loodi, lõpetab oma töö:

using Connection connection = new Connection();
connection.Send("Tere!");
// Dispose() kutsutakse siin, kui koodijupp lõpeb

Mõlemad vormid teevad sama asja. Klassikaline using (...) plokk on algajale sageli selgem, sest see näitab täpselt, kus ressurss vabastatakse.

Eluline näide: faili kirjutamine¶

Kõige sagedasem koht, kus using-klauslit päriselt kasutad, on failide ja streamidega töötamine. Klassid nagu StreamWriter ja StreamReader implementeerivad IDisposable, sest avatud fail tuleb kindlasti kinni panna.

using System.IO;

using (StreamWriter kirjutaja = new StreamWriter(@"C:\temp\paevik.txt"))
{
    kirjutaja.WriteLine("Esimene rida");
    kirjutaja.WriteLine("Teine rida");
}
// fail on siin kindlasti kinni pandud

Ilma using-klauslita jääks fail võib-olla lukku ja osa andmeid võiks kettale jõudmata kaduma minna. Failide ja streamidega tutvume lähemalt järgmistes peatükkides.

Close() ja Dispose()

Paljudel klassidel on lisaks meetod Close(). Failide puhul teeb Close() sisuliselt sama, mis Dispose() — mõlemad sulgevad ressursi. using-klausel kasutab alati Dispose()-i, seega on see kõige üldisem ja kindlam viis.

Mitu ressurssi korraga¶

Kui on vaja kasutada mitut vabastatavat objekti, saab need ühte using-lausesse panna komaga eraldatult:

using (Connection esimene = new Connection(), teine = new Connection())
{
    esimene.Saada("A");
    teine.Saada("B");
}

Ressursid vabastatakse vastupidises järjekorras: viimasena loodu suletakse esimesena. Sama tulemuse annavad ka järjestikused using-plokid, aga üks rida on lühem ja loetavam.

Millal peaks klass implementeerima IDisposable?¶

Klass peaks kasutama IDisposable liidest siis, kui ta hoiab enda käes midagi, mis tuleb käsitsi vabastada. Tüüpilised näited:

  • avatud fail või stream,
  • võrguühendus,
  • andmebaasiühendus,
  • muud välise süsteemi ressursid.

Kui klass hoiab vaid tavalisi andmeid (arvud, sõned, loendid), pole IDisposable-i vaja.

Korduvalt tekkivad vead¶

Dispose() käsitsi, aga viga katkestab töö¶

// VIGA — kui Send() viskab vea, jääb Dispose() kutsumata
var u = new Connection();
u.Send("Tere!");
u.Dispose();

// ÕIGE — using kutsub Dispose() kindlasti välja
using (var u2 = new Connection())
{
    u2.Saada("Tere!");
}

IDisposable kasutamine, aga Dispose() puudub¶

// VIGA — klass lubab IDisposable, aga meetod on puudu, kompilaator annab vea
public class Katki : IDisposable
{
    public void Send(string sõnum) { }
}

// ÕIGE — Dispose() on olemas
public class Korras : IDisposable
{
    public void Send(string sõnum) { }
    public void Dispose() { }
}

Vale meetodi nimi¶

// VIGA — meetodi nimi peab olema täpselt Dispose
public void dispose() { }   // C# on tõstutundlik!

// ÕIGE
public void Dispose() { }

Harjutused¶

  1. Loo klass Päevik, mis implementeerib IDisposable. Konstruktor trükib "Päevik avatud" ja Dispose() trükib "Päevik suletud". Kasuta klassi using-klausliga ja veendu, et mõlemad teated ilmuvad õiges järjekorras.
  2. Täienda harjutuse 1 klassi meetodiga Lisa(string tekst), mis prindib lisatava rea. Lisa using-ploki sees kolm rida ja vaata, millal täpselt "Päevik suletud" välja tuleb.
  3. Kirjuta sama programm kaks korda: üks kord kasutades using-klauslit ja teine kord kutsudes Dispose() käsitsi. Selgita kommentaarides, milline variant on turvalisem ja miks.
  4. Loo kaks erinevat vabastatavat klassi, näiteks Andmebaas ja Logi, mis mõlemad implementeerivad IDisposable. Kasuta neid ühes using-lauses ja veendu, et mõlemad vabastatakse. Jälgi, millises järjekorras Dispose() meetodid välja kutsutakse.
