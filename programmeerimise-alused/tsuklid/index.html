Tsüklid¶

Programmeerimises kasutatakse tsükleid korduvate järjestikuste tegevuste tegemiseks. Kui sama tegevust tuleb teha mitu korda, siis ei kirjuta me seda koodi mitu korda välja, vaid paneme selle tsüklisse, mis kordab seda vajaliku arvu kordi. Nii jääb kood lühemaks ja kergemini muudetavaks.

Mõtle selle peale nagu hommikuse treeningu peale: sa ei loetle üles iga kükki eraldi, vaid ütled "tee 20 kükki". Tsükkel on täpselt selline juhis arvutile — tee sama asja nii mitu korda, kui vaja.

C#-s on kolm põhilist tsüklit: while, for ja foreach. Lisaks saame tsükli tööd juhtida käskudega break ja continue.

while¶

Kõige klassikalisem on ehk while tsükkel. while töötab kuni tsükli kontrolltingimus annab tõese tulemuse. Kui kontrolltingimus annab väära tulemuse, siis lõpetab tsükkel töö. Kontrolltingimust kontrollitakse igal korral kui tsükkel nö. uuele ringile läheb.

while(kontrolltingimus)
{
    // tee midagi
}

Kui kontrolltingimus on juba alguses väär, siis ei käivitata tsükli sisu kordagi. Seetõttu nimetatakse while-i ka eelkontrolliga tsükliks.

Lihtsaim näide — loeme ja trükime arvud ühest viieni:

namespace WhileApp;

class Program
{
    static void Main(string[] args)
    {
        int arv = 1;

        while (arv <= 5)
        {
            Console.WriteLine("Arv on: " + arv);
            arv++;
        }
    }
}

Programm trükib:

Arv on: 1
Arv on: 2
Arv on: 3
Arv on: 4
Arv on: 5

Siin on kolm olulist osa:

  • algväärtus — int arv = 1; loob loenduri enne tsüklit,
  • kontrolltingimus — arv <= 5 otsustab, kas tsükkel jätkab,
  • muutmine — arv++ suurendab loendurit iga ringiga, et tsükkel kunagi lõppeks.

while on eriti hea siis, kui me ei tea ette, mitu korda tsükkel töötab. Näiteks ootame kasutajalt õiget parooli:

string parool = "";

while (parool != "salajane")
{
    Console.Write("Sisesta parool: ");
    parool = Console.ReadLine();
}

Console.WriteLine("Tere tulemast!");

Lõputu tsükkel

Kui tsükli muutuja kunagi ei muutu või kontrolltingimus jääb igavesti tõeseks, siis töötab tsükkel lõputult ja programm jääb "kinni". Veendu alati, et tsüklil oleks väljumise võimalus. 

int i = 0;
while (i < 5)
{
    Console.WriteLine(i);
    // i++ puudub → tsükkel kordub lõputult!
}

for¶

for on teine klassikaline tsükkel. Erinevalt while-ist mahub for-i sulgudesse korraga kolm asja: loenduri algväärtus, kontrolltingimus ja loenduri muutmine. for on mugav siis, kui teame ette, mitu korda tsükkel peab töötama.

for(tsükli muutuja algväärtus; kontrolltingimus; tsükli muutuja suurendamine)
{
    // tee midagi    
}

Näide, mis trükib arvud ühest kümneni:

namespace ForApp;

class Program
{
    static void Main(string[] args)
    {
        for (int i = 1; i <= 10; i++)
        {
            Console.WriteLine(i);
        }
    }
}

Sulu kolm osa eraldatakse semikooloniga ja need täidetakse nii:

  1. int i = 1 — luuakse loendur i ja antakse algväärtus (ainult korra, tsükli alguses),
  2. i <= 10 — kontrollitakse enne igat ringi, kas tsükkel jätkab,
  3. i++ — suurendatakse loendurit pärast igat ringi.

Loendur võib liikuda ka tagurpidi või sammuga üle ühe:

// Loendame tagurpidi 5-st 1-ni
for (int i = 5; i >= 1; i--)
{
    Console.WriteLine(i);
}

// Trükime ainult paarisarvud (samm 2)
for (int i = 0; i <= 20; i += 2)
{
    Console.WriteLine(i);
}

for-i kasutades on lihtne teha ka arvutusi. Näiteks arvude 1 kuni 100 summa:

int summa = 0;

for (int i = 1; i <= 100; i++)
{
    summa += i;
}

Console.WriteLine("Summa 1..100 = " + summa); // 5050

Elementide eemaldamine loendist¶

Kui eemaldame for tsükliga loendist elemente, siis peame liikuma lõpust alguse poole (kahaneva indeksiga). Vaatame kõigepealt, mis juhtub valesti, kui liikuda ettepoole.

using System.Collections.Generic;

List<int> arvud = new List<int> { 2, 4, 6, 8 };

// VALE — eemaldamine ettepoole liikudes
for (int i = 0; i < arvud.Count; i++)
{
    if (arvud[i] % 2 == 0)
    {
        arvud.RemoveAt(i);
    }
}

// Tulemus: { 4, 8 } — pooled paarisarvud jäid alles!

Miks nii juhtub? Kui eemaldame loendist elemendi indeksil i, siis kõik järgnevad elemendid nihkuvad ühe võrra vasakule. Element, mis oli indeksil i + 1, satub nüüd indeksile i. Aga tsükkel liigub kohe edasi indeksile i + 1 ja jätab selle nihkunud elemendi kontrollimata.

Samm-sammult:

  1. i = 0 → arvud[0] on 2, eemaldame selle. Loend on nüüd { 4, 6, 8 }, kus 4 on indeksil 0.
  2. i = 1 → tsükkel läheb edasi ja vaatab arvud[1], mis on nüüd 6 (mitte 4!). 4 jäi vahele. Eemaldame 6. Loend on { 4, 8 }.
  3. i = 2 → 2 ei ole väiksem kui loendi pikkus 2, seega tsükkel lõpeb.

Õige lahendus on liikuda tagant ettepoole:

using System.Collections.Generic;

List<int> arvud = new List<int> { 2, 4, 6, 8 };

// ÕIGE — eemaldamine tagant ettepoole liikudes
for (int i = arvud.Count - 1; i >= 0; i--)
{
    if (arvud[i] % 2 == 0)
    {
        arvud.RemoveAt(i);
    }
}

// Tulemus: { } — kõik paarisarvud on eemaldatud

Tagant ettepoole liikudes on eemaldamine ohutu, sest nihkuvad ainult need elemendid, mis asuvad eemaldatavast taga ja mida me oleme juba läbi vaadanud. Meie ees (väiksematel indeksitel) olevad elemendid jäävad paigale.

Reegel

Kui eemaldad tsükliga loendist elemente, liigu alati tagant ettepoole. Nii ei jää ükski element vahele.

foreach¶

foreach on tsükkel, mis käib läbi kõikide kogumi (massiivi või loendi) elementide. Erinevalt for-ist ei pea me ise indeksit haldama ega teadma elementide arvu — foreach võtab iga elemendi järjest ette ja paneb selle muutujasse.

foreach (elemendi_tüüp muutuja in kogum)
{
    // tee midagi muutujaga
}

Näide, kus tervitame iga nime massiivist:

namespace ForeachApp;

class Program
{
    static void Main(string[] args)
    {
        string[] nimed = { "Mari", "Jaan", "Kati", "Peeter" };

        foreach (string nimi in nimed)
        {
            Console.WriteLine("Tere, " + nimi + "!");
        }
    }
}

Sama töötab ka loendiga:

using System.Collections.Generic;

List<int> numbrid = new List<int> { 10, 20, 30, 40 };
int summa = 0;

foreach (int arv in numbrid)
{
    summa += arv;
}

Console.WriteLine("Summa: " + summa); // 100

foreach ei anna indeksit

foreach annab kätte elemendi enda, mitte selle järjekorranumbrit. Kui vajame iga elemendi juures ka indeksit, tuleks kasutada for-i.

foreach-iga ei tohi kogumit muuta

Kui loendit foreach-iga läbides seda muuta (lisada või eemaldada), viskab C# erindi InvalidOperationException: Collection was modified; enumeration operation may not execute. 

List<int> arvud = new List<int> { 2, 4, 6, 8 };

// VIGA — viskab InvalidOperationException
foreach (int arv in arvud)
{
    if (arv % 2 == 0)
    {
        arvud.Remove(arv);
    }
}
Põhjus: List<T> hoiab sees versiooninumbrit ja foreach-i loendur kontrollib seda igal sammul — kui see muutub, katkestab ta töö.

Kasuta selle asemel: - for tsüklit tagant ettepoole (nagu eelmises näites), - arvud.RemoveAll(arv => arv % 2 == 0); — kõige lühem viis, - kopeeri allesjäävad uude loendisse ja asenda vana.

do ... while¶

do ... while on sarnane while-iga, kuid kontrolltingimust ei kontrollita mitte enne, vaid pärast tsükli sisu. See tähendab, et tsükli sisu täidetakse alati vähemalt üks kord, ükskõik kas tingimus on tõene või väär.

do
{
    // tee midagi
} while(kontrolltingimus);

Võrdleme seda hariliku while-iga:

int i = 10;

// while: tingimus on kohe väär → sisu ei täideta kordagi
while (i < 5)
{
    Console.WriteLine(i);
}

// do ... while: sisu täidetakse alati vähemalt üks kord
do
{
    Console.WriteLine(i);
    i++;
} while (i < 5);

Esimene tsükkel ei trüki midagi, sest 10 < 5 on väär. Teine trükib 10, sest sisu täidetakse enne tingimuse kontrollimist.

do ... while sobib hästi siis, kui tahame midagi kindlasti vähemalt korra teha. Näiteks küsime kasutajalt arve, kuni ta sisestab 0:

int arv;

do
{
    Console.Write("Sisesta arv (0 lõpetab): ");
    arv = int.Parse(Console.ReadLine());
} while (arv != 0);

Console.WriteLine("Tsükkel lõppes.");

Näide: Azure Blob Storage'ist failide lugemine lehe kaupa¶

Azure Blob Storage'is võib ühes konteineris olla tuhandeid faile. Neid ei tagastata korraga, vaid lehe (page) kaupa — iga päring annab piiratud arvu kirjeid ja kaasa jätkamistokeni (ContinuationToken), millega küsitakse järgmist lehte. Viimasel lehel on token tühi. Kuna esimene päring tuleb teha alati, sobib siia hästi do ... while.

using System.Linq;
using Azure;
using Azure.Storage.Blobs;
using Azure.Storage.Blobs.Models;

// Loome kliendi, mis osutab konteinerile "minu-konteiner"
var container = new BlobContainerClient(connectionString, "minu-konteiner");

string token = null; // esimesel päringul jätkamistokenit veel pole
int arv = 0;         // loeme kokku, mitu blob'i leidsime

do
{
    // Küsi üks leht (kuni 100 blob'i) alates eelmisest tokenist.
    // `.First()` võtab lehekogumist esimese ehk käesoleva lehe.
    Page<BlobItem> page = container
        .GetBlobs()
        .AsPages(token, pageSizeHint: 100)
        .First();

    // Käime läbi kõik selle lehe blobid
    foreach (BlobItem blob in page.Values)
    {
        Console.WriteLine(blob.Name); // trükime faili nime
        arv++;                        // ja loendame selle
    }

    // Võtame vastusest järgmise lehe tokeni.
    // Viimasel lehel on see tühi, mis lõpetab tsükli.
    token = page.ContinuationToken;
} while (!string.IsNullOrEmpty(token));

Console.WriteLine($"Kokku blobe: {arv}");
  • GetBlobs() tagastab lehekülgede kaupa loetava kogumi.
  • AsPages(token, pageSizeHint: 100) piirab ühe lehe 100 blob'iga ja alustab antud tokenist.
  • page.Values on selle lehe blobid, page.ContinuationToken viib järgmise lehe juurde.

break ja continue¶

Mõnikord tahame tsükli tavalist kulgemist katkestada. Selleks on kaks käsku:

  • break — väljub tsüklist kohe ja täielikult,
  • continue — jätab ülejäänud osa sellest ringist vahele ja liigub järgmise ringi juurde.

break on mugav siis, kui oleme vajaliku leidnud ja edasi pole mõtet otsida:

for (int i = 1; i <= 10; i++)
{
    if (i == 5)
    {
        break; // lõpetame tsükli kohe
    }

    Console.WriteLine(i);
}

See programm trükib ainult 1 2 3 4, sest kui i jõuab viieni, tullakse tsüklist välja.

continue seevastu jätab vahele ainult selle ringi:

for (int i = 1; i <= 10; i++)
{
    if (i % 2 == 0)
    {
        continue; // jätame paarisarvud vahele
    }

    Console.WriteLine(i); // trükib 1, 3, 5, 7, 9
}

break ka switch-lauses

Nagu tingimuslausete peatükis nägime, tähendab break ka switch-lauses väljumist. Kontekst määrab, millest parasjagu välja tullakse.

Kokkuvõte¶

Tsükkel Millal kasutada
while Kui kordade arv pole ette teada, sõltub tingimusest
do ... while Kui sisu peab täituma vähemalt üks kord
for Kui kordade arv on ette teada
foreach Kui tuleb läbi käia kõik kogumi elemendid
Käsk Tähendus
break Väljub tsüklist kohe
continue Jätab selle ringi vahele ja läheb järgmise juurde

Harjutused¶

  1. Kirjuta programm, mis kasutab while tsüklit ja trükib arvud 1 kuni 10 kasvavas järjekorras.
  2. Kirjuta programm, mis kasutab for tsüklit ja trükib tagurpidi arvud 10 kuni 1.
  3. Arvuta for tsükliga kõikide paarisarvude summa vahemikus 1 kuni 50.
  4. Loo massiiv oma lemmiklaulude nimedega ja trüki need foreach tsükliga ekraanile.
  5. Loo loend arvudest ja leia foreach tsükliga nii nende summa kui ka suurim element.
  6. Küsi kasutajalt while tsüklis arve seni, kuni ta sisestab 0. Seejärel trüki sisestatud arvude summa.
  7. Kirjuta programm, mis trükib for tsükliga korrutustabeli arvule 7 (7 × 1 kuni 7 × 10).
  8. Kasuta break-i, et leida esimene arv vahemikus 1 kuni 100, mis jagub nii 3-ga kui ka 5-ga.
  9. Kasuta continue-i, et trükida arvud 1 kuni 20, jättes vahele kõik arvud, mis jaguvad 3-ga.
  10. Kirjuta programm, mis küsib kasutajalt parooli. Anna kasutajale kolm katset for tsükliga ja katkesta break-iga, kui parool on õige.
