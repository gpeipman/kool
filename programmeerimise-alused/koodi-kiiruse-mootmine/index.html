Koodi kiiruse mõõtmine¶

Programme kirjutades tunneme huvi ka selle vastu kui kiiresti või aeglaselt üks või teine osa koodis töötab. Eriti huvitab kiirus meid siis kui maadleme mõne jõudluse probleemiga.

Stopper - Stopwatch¶

Koodi kiiruse mõõtmiseks kasutame Stopwatcher klassi. See on nagu tarkvaraline stopper. Me saame selle käima panna ja hiljem peatada. Siin on näide selle klassi kasutamisest.

var watch = new Stopwatch();

watch.Start();
Thread.Sleep(2000);
watch.Stop();

Console.WriteLine("Aega läks: " + watch.Elapsed);

using System.Diagnostics;

namespace StopwatchApp;

class Program
{
    static void Main(string[] args)
    {
        var watch = new Stopwatch();

        watch.Start();
        Thread.Sleep(2000);
        watch.Stop();

        Console.WriteLine("Aega läks: " + watch.Elapsed);
    }
}

Miks kasutame mõõtmiseks Stopwatch klassi?¶

Igasuguse kiiruse mõõtmise juures on esimene küsimus: millega me mõõdame? Esmapilgul tundub loomulik võtta enne mõõdetava koodi jooksutamist hetk DateTime.Now-ist, pärast seda uuesti ja lahutada:

var algus = DateTime.Now;

// mõõdetav kood

var lõpp = DateTime.Now;

Console.WriteLine("Aega läks: " + (lõpp - algus));

See lahendus küll töötab, aga on kiiruse mõõtmiseks halb. DateTime.Now on mõeldud kellaaja kuvamiseks inimesele — selle ülesanne on öelda, mis kell parasjagu on, mitte mõõta mikrosekundeid. Sellel on kolm probleemi:

  • Süsteemi kella aetakse aeg-ajalt õigeks näiteks kellaaja sünkroniseerimise teel. Sel hetkel võib kellaaeg hüpata edasi või tagasi, mis teeb mõõtmistulemuse valeks.
  • DateTime.Now väikseim eristatav ajavahemik on piiratud. Windowsil on see suurusjärgus 15 millisekundit ehk 15 tuhandikku sekundit. Kiire kood, mis töötab mikrosekunditega (tuhandikud millisekundit), jääb sellisest mõõtmisest nähtamatuks.
  • Täpsust mõjutab ka see, mis kasutaja arvutis sel hetkel veel toimub — taustaülesanded ja operatsioonisüsteemi üldine seis.

Stopwatch klass on loodud just selle ülesande jaoks: väikeste ajavahemike täpseks mõõtmiseks. Ta kasutab süsteemi kõrge resolutsiooniga loendurit ja mõõdab aega mikrosekundite täpsusega. Tema kasutamine ei koorma praktiliselt programmi üldse. Sealt ka kogu peatüki jooksul kasutatav muster:

var watch = new Stopwatch();

watch.Start();

// mõõdetav kood

watch.Stop();

Console.WriteLine("Aega läks: " + watch.Elapsed);

using System.Diagnostics

Stopwatch asub nimeruumis System.Diagnostics. Uuemad Visual Studio mallid toovad selle tihti ise sisse, muul juhul lisame programmi ülaossa rea using System.Diagnostics;.

Faili kirjutamine File klassi abil¶

Varasemast on File klass meile juba tuttav. Selle klassi abil saime failidega teha mitmeid toiminguid. Nüüd püüame selle klassi abil luua logifaili ja kirjutada sinna 100000 kannet. Seejuures mõõdame kirjutamisele kulunud aega.

var watch = new Stopwatch();
var fileName = "log-file.txt";

watch.Start();

for(var i = 0; i < 100000; i++)
{
    File.AppendAllText(fileName, (i + 1) + Environment.NewLine);
}

watch.Stop();

Console.WriteLine("Aega läks: " + watch.Elapsed);

using System.Diagnostics;
using System.IO;

namespace FileAppendApp;

class Program
{
    static void Main(string[] args)
    {
        var watch = new Stopwatch();
        var fileName = "log-file.txt";

        watch.Start();

        for (var i = 0; i < 10000; i++)
        {
            File.AppendAllText(fileName, (i + 1) + Environment.NewLine);
        }

        watch.Stop();

        Console.WriteLine("Aega läks: " + watch.Elapsed);
    }
}

Selle teksti kirjutamise ajal andis arvuti tulemuseks 00:01:15.4007626 (üks minut ja 15 sekundit).

Faili kirjutamine streami klasside abil¶

Kirjutame selle koodi nüüd ümber streami klasse kasutades ja mõõdame ka selle kiiruse.

var watch = new Stopwatch();
var fileName = "log-file.txt";

using(var fileStream = new FileStream(fileNamem, ...))
using(var writer = new StreamWriter(fileStream))
{
    watch.Start();

    for(var i = 0; i < 100000; i++)
    {
        writer.WriteLine(i + 1);
    }

    watch.Stop();
}
Console.WriteLine("Aega läks: " + watch.Elapsed);

using System.Diagnostics;
using System.IO;

namespace MathApp;

class Program
{
    static void Main(string[] args)
    {
        var watch = new Stopwatch();
        var fileName = "log-file.txt";

        using (var fileStream = new FileStream(fileName, FileMode.OpenOrCreate))
        using (var writer = new StreamWriter(fileStream))
        {
            watch.Start();

            for (var i = 0; i < 10000; i++)
            {
                writer.WriteLine(i + 1);
            }

            watch.Stop();
        }
        Console.WriteLine("Aega läks: " + watch.Elapsed);
    }
}

Seekord kulus skriptil sama ülesande jaoks aega 00:00:00.0012375.

Mis juhtus?¶

Kui me neid kahte ajakulu võrdleme, siis streami kasutamine on 62500 korda kiirem. Millest selline vahe?

File.AppendAllText() teeb kordi rohkem tegevusi kui streami klassid. Kui streami korral toimub kirjutamine samasse streami, siis File klassi korral on töörütm teine.

for(var i = 0; i < 100000; i++)
{
    // Ava fail
    // Vii faili lugemise/kirjutamise viit faili lõppu
    // Kirjuta faili uus rida
    // Sulge fail
}

Suure erinevuse tingisid seega täiendavad toimingud, mida File klass meile nähtamatult teeb. Üks saladus on ka streami klassidel - streami klassid ei kirjuta väljundit faili kohe kui käsime. Sisemiselt hoiavad need klassid mälupuhvrit, kuhu mie antud tekst kirjutatakse. Kui see puhver on täis, siis kirjutatakse selle sisu kettale.

Harjutused¶

  1. Loo programm, mis mõõdab Stopwatch-iga, kui kaua võtab aega arvude 1 kuni 10000 summa arvutamine for-tsükliga. Kuva tulemus konsoolile watch.Elapsed abil. Proovi hiljem sama arvutust teha ka 100000 arvuga ja võrdle, kui palju aega juurde tuli.

  2. Kleebi oma projekti peatükis olevad kaks näidet — File.AppendLine()-ga ja streami klassidega logifaili kirjutamine. Loo ~100000 kande teisene logifail mõlema variandiga ja mõõda mõlema kulgemist. Kirjuta tulemused üles ja mõõda veel teine kord — kas tulemused on sarnased?

  3. Võrdle kaht mõõteviisi: mõõda sama väga kiire operatsioon (näiteks i * 2 100000 korda) kõigepealt DateTime.Now lahutamisega ja siis Stopwatch-iga. Proovi mõlemat mõõtmist mitu korda ja vaata, kui palju tulemused erinevad. Sellest on hea näha, miks Stopwatch usaldusväärsem on.

  4. Kirjuta programm, mis testib puhverdamist: kirjuta StreamWriter-iga faili 10000 rida. Mõõda, kui kaua see aega võtab, kui puhver lastakse iga 1000 rea järel tühjaks writer.Flush()-iga, ja võrdle aega variandiga, kus Flush()-i ei kasuta.

  5. Sama ülesanne mitu korda: pane ühe tsükli sisse mõõtmine nii, et programm mõõdab sama ülesande täitmise 5 korda ning jagab kogu aja 5-ga. Nii saame ülesande keskmise kestuse, mis on täpsem kui üksainus mõõtmine. (Vihje: hoia igal ringil Stopwatch eraldi või kasuta watch.Restart().)
