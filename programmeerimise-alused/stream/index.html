Streamid¶

Failide peatükis õppisime faile lugema ja kirjutama nii, et terve fail laeti korraga mällu: File.ReadAllText() loeb kogu faili üheks sõneks, File.ReadAllLines() aga kogu faili ridade massiiviks. See sobib väikeste failide jaoks.

Aga mis saab siis, kui fail on tohutusuur — näiteks mitme gigabaidine logifail ehk programmi töö käigus tekkinud sündmuste päevik? Terve faili mällu laadimine viib programmi kokku. Lahendus on stream.

Mis on stream?¶

Stream (eesti keeles voog) on andmete pidev liikumine allikast sihtkohta. Streami asemel, et terve fail korraga mällu laadida, loeme andmeid väikeste tükkidena — nagu jooksaks vett läbi õlekõrre.

Mõtle selle peale nagu muusika kuulamisel: striiminguteenus ei laadi alla terve albumi korraga. See mängib muusikat lõigukaupa, samal ajal kui uued lõigud jõuavad kohale.

C#-s on streamideks klassisüsteem: kõigil neil on ühine emaklass Stream. Kaks kõige tavalisemat streami, mida me kasutame, on:

Klass Töötab Milleks
FileStream faili sisu faili avamine streamina
StreamReader teksti tekstiridade lugemine
StreamWriter teksti tekstiridade kirjutamine

Kõik streamid asuvad nimeruumis System.IO, nii et alustame tavapärase reaga:

using System.IO;

Faili avamine streamina — FileStream¶

FileStream ühendab meid failiga. Avamisel peame ütlema, kuidas me faili kohtleme — FileMode väärtusega:

FileMode Tähendus
Open Ava olemasolev fail
Create Loo uus fail (vana sisu kustutatakse)
OpenOrCreate Ava fail või loo, kui teda pole
Append Ava fail ja mine lõppu juurde kirjutamiseks
CreateNew Loo uus fail; vea, kui fail juba olemas 
using System.IO;

string tee = @"C:\temp\tervitus.txt";
FileStream voog = new FileStream(tee, FileMode.OpenOrCreate);

Avatud stream tuleb ka kinni panna, sest muidu jääb fail lukku ja andmed võivad kaduma minna. Lähemalt räägime sellest allpool.

Veel üks viis faili avamiseks

File klassil on ka oma meetodid streamide tegemiseks: File.OpenRead(tee), File.OpenWrite(tee) ja File.Open(tee, FileMode). Need on lühike tee sama asja juurde.

Kirjutamine StreamWriter-iga¶

StreamWriter kirjutab faili teksti ridade kaupa. Tähtsad meetodid on WriteLine() (rida koos reavahetusega) ja Write() (tekst ilma reavahetuseta).

using System.IO;

string tee = @"C:\temp\paevik.txt";
StreamWriter kirjutaja = new StreamWriter(tee);

kirjutaja.WriteLine("Esimene rida");
kirjutaja.WriteLine("Teine rida");

kirjutaja.Close();

using System.IO;

namespace FilesApp;

class Program
{
    static void Main(string[] args)
    {
        string tee = @"C:\temp\paevik.txt";
        StreamWriter kirjutaja = new StreamWriter(tee);

        kirjutaja.WriteLine("Esimene rida");
        kirjutaja.WriteLine("Teine rida");

        kirjutaja.Close();
    }
}

Close() paneb streami kinni. See kirjutab allesjäänud andmed kettale ja annab faili teiste programmide jaoks vabaks.

Lisamine faili lõppu¶

StreamWriter ei pea alati faili algusest alustama. Teine argument true tähendab, et uued read lisatakse faili lõppu, vana sisu alles jääb:

using System.IO;

StreamWriter kirjutaja = new StreamWriter(@"C:\temp\paevik.txt", true);

kirjutaja.WriteLine("Uus kanne");
kirjutaja.WriteLine("Veel üks kanne");

kirjutaja.Close();

using System.IO;

namespace FilesApp;

class Program
{
    static void Main(string[] args)
    {
        StreamWriter kirjutaja = new StreamWriter(@"C:\temp\paevik.txt", true);

        kirjutaja.WriteLine("Uus kanne");
        kirjutaja.WriteLine("Veel üks kanne");

        kirjutaja.Close();
    }
}

Nii saame programmidele logisid ehk sündmuste päevikuid juurde kirjutada, ilma et varasem kirjutatu kaoks.

Lugemine StreamReader-iga¶

StreamReader loeb faili teksti ridade kaupa. Ridade kaupa lugemisel peame teadma, millal fail lõppeb: ReadLine() tagastab null, kui rohkem ridu pole.

using System.IO;

StreamReader lugeja = new StreamReader(@"C:\temp\paevik.txt");

string rida;
while ((rida = lugeja.ReadLine()) != null)
{
    Console.WriteLine(rida);
}

lugeja.Close();

using System.IO;

namespace FilesApp;

class Program
{
    static void Main(string[] args)
    {
        StreamReader lugeja = new StreamReader(@"C:\temp\paevik.txt");

        string rida;
        while ((rida = lugeja.ReadLine()) != null)
        {
            Console.WriteLine(rida);
        }

        lugeja.Close();
    }
}

Kuidas while koos lugemisega töötab

while ((rida = lugeja.ReadLine()) != null) loeb igal sammul uue rea muutujasse rida ja kontrollib, kas rida on olemas — kui ReadLine() tagastab null, on fail lõppenud ja tsükkel peatub.

Kogu sisu korraga¶

Kui tahame kogu sisu ühe korraga, on StreamReader-il olemas ReadToEnd():

using System.IO;

StreamReader lugeja = new StreamReader(@"C:\temp\paevik.txt");

string koguSisu = lugeja.ReadToEnd();
Console.WriteLine(koguSisu);

lugeja.Close();

using System.IO;

namespace FilesApp;

class Program
{
    static void Main(string[] args)
    {
        StreamReader lugeja = new StreamReader(@"C:\temp\paevik.txt");

        string koguSisu = lugeja.ReadToEnd();
        Console.WriteLine(koguSisu);

        lugeja.Close();
    }
}

Ressursside vabastamine — using-lause¶

Streami kinnipanemata jätmine on ohtlik: fail võib teistele programmidele lukku jääda ja kirjutamisel võib osa andmeid kaduma minna. Õige viis on kasutada using-lauset, mis paneb streami automaatselt kinni — ka siis, kui programmis juhtub viga.

using System.IO;

using (StreamWriter kirjutaja = new StreamWriter(@"C:\temp\paevik.txt", true))
{
    kirjutaja.WriteLine("Esimene rida");
    kirjutaja.WriteLine("Teine rida");
}
// siin on stream juba automaatselt kinni pandud

Kõik edasised näited kasutavad using-lauset.

Lühike vorm valikuliselt

Uusemates C# versioonides (8.0 ja uuemad) on olemas ka lühem vorm using StreamWriter kirjutaja = new StreamWriter(tee);. Sel juhul pandakse stream kinni programmi lõpus, aga klassikaline using-blokk on selge ja soovitatav alustajale.

Näide: logifaili lugemine vealehtede leidmiseks¶

Oletame, et meil on logifail, kus igal real on üks sündmus. Loeme faili rea kaupa ja loeme kokku, mitu ERROR sündmust sealt leiame:

using System;
using System.IO;

string tee = @"C:\temp\programmi.log";

int errorArv = 0;

using (StreamReader lugeja = new StreamReader(tee))
{
    string rida;
    while ((rida = lugeja.ReadLine()) != null)
    {
        if (rida.Contains("ERROR"))
        {
            errorArv++;
        }
    }
}

Console.WriteLine("ERROR-ridu leiti: " + errorArv);

using System;
using System.IO;

namespace FilesApp;

class Program
{
    static void Main(string[] args)
    {
        string tee = @"C:\temp\programmi.log";

        int errorArv = 0;

        using (StreamReader lugeja = new StreamReader(tee))
        {
            string rida;
            while ((rida = lugeja.ReadLine()) != null)
            {
                if (rida.Contains("ERROR"))
                {
                    errorArv++;
                }
            }
        }

        Console.WriteLine("ERROR-ridu leiti: " + errorArv);
    }
}

Sellist programmi saab jooksutada ka hiigelsuure logifaili peal — mälus hoitakse korraga vaid ühte rida, mitte tervet faili.

Millal kasutada File ja millal streami?¶

Failide peatükist tuntud File meetodid ja streamid teevad lihtsate ülesannete korral sama asja. Vale valik on siiski olemas:

Olukord Sobiv valik
Väike fail, mida tuleb lugeda ühe hooga File.ReadAllText()
Väike fail, read korraga File.ReadAllLines()
Suur fail, mida tuleb töödelda rea kaupa StreamReader
Andmete pidev juurde kirjutamine (logid) StreamWriter (append)
Faili kopeerimine tükikaupa FileStream

Sageli tekkinud vead¶

using System.IO puudumine¶

// VIGA — StreamReader klass puudub
StreamReader lugeja = new StreamReader(tee); // Viga!

// ÕIGE
using System.IO;
StreamReader lugeja2 = new StreamReader(tee);

Streami kinnipanemata jätmine¶

using System.IO;

// VIGA — Close() puudub, fail jääb lukku ja andmed võivad kaduda
StreamWriter kirjutaja = new StreamWriter(tee);
kirjutaja.WriteLine("Tere!");

// ÕIGE — using-lause paneb streami automaatselt kinni
using (StreamWriter kirjutaja2 = new StreamWriter(tee))
{
    kirjutaja2.WriteLine("Tere!");
}

ReadLine() ilma null-kontrollita¶

using System.IO;

// VIGA — faili lõpus annab ReadLine() null ja programm jookseb kokku
string rida = lugeja.ReadLine();
while (true)
{
    Console.WriteLine(rida.ToUpper());
}

// ÕIGE — kontrollime, kas rida ikka on olemas
using (StreamReader lugeja2 = new StreamReader(tee))
{
    string rida2;
    while ((rida2 = lugeja2.ReadLine()) != null)
    {
        Console.WriteLine(rida2.ToUpper());
    }
}

Kõik meetodid kokkuvõttes¶

Objekt / meetod Tähendus
new FileStream(tee, FileMode) Faili avamine streamina
new StreamWriter(tee) Kirjutaja faili algusest
new StreamWriter(tee, true) Kirjutaja faili lõppu lisamiseks
StreamWriter.WriteLine(tekst) Kirjutab rea
StreamWriter.Write(tekst) Kirjutab teksti ilma reavahetuseta
StreamWriter.Flush() Surub puhvris olevad andmed faili
new StreamReader(tee) Lugeja faili algusest
StreamReader.ReadLine() Loeb ühe rea; faili lõpus null
StreamReader.ReadToEnd() Loeb kogu ülejäänud sisu
using (...) Sulgeb streami automaatselt

Harjutused¶

  1. Loo programm, mis kirjutab logifaili log.txt programmi käivitamise ja lõpetamise aja. Kasuta StreamWriter-it koos FileMode.Append või true parameetriga ja DateTime.Now kuupäevaga, et päevik oleks täidetav mitu korda ilma vana sisu kaotamata.
  2. Kirjuta programm, mis loeb StreamReader-iga ridade kaupa faili linnad.txt ja trükib iga linna koos reanumbriga: 1. Tallinn, 2. Tartu jne.
  3. Loo programm, mis küsib kasutajalt üksteise järel sõnu ja salvestab need ridade kaupa faili sonad.txt. Küsimine lõpeb, kui kasutaja sisestab sõna lõpp.
  4. Kirjuta programm, mis loeb faili programmi.log rea kaupa ja trükib välja ainult read, mis algavad ERROR — nii saame logist vead välja filtreerida.
  5. Loo koopiaprogramm: programm loeb faili allikas.txt rea kaupa StreamReader-iga ja kirjutab need StreamWriter-iga faili koopia.txt. Kasuta mõlema jaoks using-lauset. Faili lõpus ütle, mitu rida kopeeriti.
