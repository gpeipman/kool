Data Transfer Object (DTO)¶

DTO (Data Transfer Object) on lihtne klass, mille ülesanne on andmeid ühest kohast teise transportida. DTO-d on eriti tähtsad veebirakendustes, kus andmed liiguvad serveri ja kliendi vahel. DTO on klass, mis sisaldab ainult omadusi – mingit loogikat, arvutusi või reegleid seal ei ole. Tema ainus töö on andmete kandmine.

public class BookDto
{
    public int Id { get; set; }
    public string Title { get; set; }
    public string Author { get; set; }
    public int Year { get; set; }
    public bool IsAvailable { get; set; }
}

Miks DTO-d on vaja?¶

1. Sa ei taha kõike avalikustada¶

Andmebaasi klass (entiteet) võib sisaldada selliseid omadusi, mida kasutajale näidata ei tohi.

Näiteks on Liikmel parooliräsi ja sisemine liikmenumber, mida API kasutajale tagastada ei tohiks:

// Entiteet – andmebaasi tabel, sisaldab kõike
public class Member
{
    public int Id { get; set; }
    public string FirstName { get; set; }
    public string LastName { get; set; }
    public string Email { get; set; }
    public string PasswordHash { get; set; }   // ⚠️ seda ei tohi näidata!
    public string Phone { get; set; }
    public DateTime DateRegistered { get; set; }
}

// DTO – ainult see, mida kasutaja tohib näha
public class MemberDto
{
    public int Id { get; set; }
    public string FirstName { get; set; }
    public string LastName { get; set; }
    public string Email { get; set; }
}

2. Väljastatakse ainult vajalikud andmed¶

Mõnikord on entiteedil 15 omadust, aga kasutaja vajab ainult 4. DTO-ga saad otsustada, mis andmed välja jõuavad.

3. Väldid tsüklilisi viiteid¶

Entiteedid on omavahel seotud (Liige → Laenutus → Raamat). Ilma DTO-ta võib JSON-i sattuda lõputu ahel, kus raamat viitab liikmele, kes viitab raamatule jne. DTO-ga paned ise paika, mida tagastada.

4. Lahutab andmebaasi ja API¶

Kui muudad andmebaasi struktuuri (entiteeti), ei pea API välisilme (DTO) muutuma – ja vastupidi. DTO on puhver kahe maailma vahel.

Mille poolest DTO erineb entiteedist ja domeeniklassist?¶

Entiteet (data class) Domeeniklass DTO
Seos andmebaasiga Otsene – vastab tabelile (EF Core) Ei puutu andmebaasiga Ei puutu andmebaasiga
Sisu Andmed + seosed + võõrvõtmed Andmed + loogika + meetodid Ainult andmed
Meetodid Puuduvad või minimaalsed Äriloogika (nt ArvutaTrahv()) Puuduvad
Eesmärk Andmebaasiridade esitamine Rakenduse reeglite esitamine Andmete transportimine
Kasutuskoht EF Core / DbContext Ärilogika kiht API piir (controllers)
Levinud nime Liige Liige LiigeDto

Lühidalt:

  • Entiteet – kuidas andmed on andmebaasis salvestatud
  • Domeeniklass – kuidas rakendus käitub (sisaldab reegleid ja tegevusi)
  • DTO – kuidas andmed liiguvad rakenduse piiride vahel

Näide: DTO kasutamine API-s¶

1. Entiteet (andmebaas)¶

public class Book
{
    public int Id { get; set; }
    public string Title { get; set; }
    public string Auhtor { get; set; }
    public string Isbn { get; set; }
    public int YearPublished { get; set; }
    public int Pages { get; set; }
    public bool IsAvailable { get; set; }

    public List<Borrowing> Borrowings { get; set; }
}

2. DTO (API vastus)¶

public class BookDto
{
    public int Id { get; set; }
    public string Title { get; set; }
    public string Author { get; set; }
    public int YearPublished { get; set; }
}

Pane tähele: Isbn, Pages ja Borrowings pole DTO-s – kasutaja neid ei vaja.

3. Entiteedist DTO-ks teisendamine¶

public class ListBooksQueryHandler
{
    private readonly LibraryContext _dbContext;

    public HangiRaamatudQueryHandler(LibraryContext dbContext)
    {
        _dbContext = dbContext;
    }

    public async Task<List<BookDto>> Handle(ListBooksQuery query)
    {
        var books = await _dbContext.Books.ToListAsync();

        return books.Select(r => new BookDto
        {
            Id = r.Id,
            Title = r.Title,
            Author = r.Author,
            YearPublished = r.YearPublished
        }).ToList();
    }
}

4. Vastupidises suunas – DTO-st entiteediks¶

Sisselogimisel või lisamisel liiguvad andmed vastupidises suunas: DTO (kasutaja saadab) → entiteet (salvestame).

public class SaveBookCommandHandler
{
    private readonly LibraryContext _dbContext;

    public SaveBookCommandHandler(LibraryContext dbContext)
    {
        _dbContext = dbContext;
    }

    public async Task Handle(SaveBookDto dto)
    {
        var book = new Book
        {
            Title = dto.Title,
            Author = dto.Author,
            Isbn = dto.Isbn,
            YearPublished = dto.YearPublished,
            Pages = dto.Pages,
            IsAvailable = true
        };

        _dbContext.Books.Add(book);
        await _dbContext.SaveChangesAsync();
    }
}

Automapper¶

Päris projektides tehakse entiteet↔DTO teisendusi tihti Automapper-nimelise NuGeti paketiga, mis vähendab käsitsi kirjutatud koodi hulka. Alustamiseks on aga oluline teha teisendusi ise – siis saad aru, mis tegelikult toimub.

Millal DTO-d kasutada?¶

Kasuta DTO-d alati, kui:

  • Andmed ületavad API piiri (sisenevad või väljuvad rakendusest)
  • Sa ei taha kõiki entiteedi omadusi välja näidata
  • Entiteet sisaldab seoseid, mida ei tohi JSON-i sattuda

Ära kasuta DTO-d:

  • Rakenduse sees, kui entiteet/domeeniklass teeb sama töö
  • Kui DTO on identne entiteediga ega lisa väärtust

Kokkuvõte¶

  • DTO on lihtne klass, mis kannab andmeid rakenduse piiride vahel
  • Entiteet on seotud andmebaasiga, domeeniklass äriloogikaga, DTO aga mõlemaga mitte
  • DTO aitab peita tundlikud andmed (nt parool) ja mittevajalikud väljad
  • DTO hoiab andmebaasi muudatused API välisilme eest varjul
  • Kasuta DTO-d API piiril – sealt liiguvad andmed serveri ja kliendi vahel
