Objekt-orienteeritud modelleerimine¶

Enne kui hakkad koodi kirjutama, pead plaani tegema. Objekt-orienteeritud modelleerimine tähendab, et mõtled läbi, milliseid klasse sul vaja on ja kuidas need omavahel seotud on. Lisaks tuleb mõelda veel millised omadused klassidel on ja millised reeglid omaduste väärtustele kehtivad.

Selles peatükis teeme läbi ühe lihtsa harjutuse. Meil on lähteülesanne ning selle põhjal tuvastame klassid, loome klassiskeemi ja dokumenteerime need klassid. Pärast teete samad sammud läbi iseseisvalt oma ainetöö lähteülesande põhjal.

Ülesanne¶

Allpool on kirjeldatud ühe veebirakenduse nõuded. Sinu ülesanne on:

  1. Tuvasta klassid – loe läbi nõuded ja leia, milliseid klasse on vaja
  2. Tuvasta iga klassi omadused – mis andmeid klass hoiab?
  3. Tuvasta andmetüübid – iga omaduse tüüp (int, string, double, DateTime, bool jne)
  4. Tuvasta reeglid – mis piirangud igale omadusele rakenduvad?
  5. Tee klassiskeem – kasuta diagrams.net
  6. Dokumenteeri klassid – kirjuta iga klassi kohta lahti omadused, tüübid ja reeglid

Lähteülesanne: Raamatukogu süsteem¶

Tahame teha programmi, mis aitab kooli raamatukogu hallata. Allpool on kirjas, mida programm peab tegema.

Raamatud: Igal raamatul on pealkiri ja autor. Raamatul on ka ISBN-number, mis on alati täpselt 13 tähemärki pikk. Raamatul on väljaandmise aasta – see peab olema vähemalt 1900 ja mitte suurem kui tänane aasta. Raamatul on lehekülgede arv, mis peab olema vähemalt 1. Raamat võib olla kas saadaval või välja laenutatud.

Kasutajad: Igal kasutajal on ees- ja perekonnanimi. Kasutajal on e-posti aadress, mis on kohustuslik. Kasutajal on telefoninumber – see pole kohustuslik, aga kui on, siis peab olema täpselt 8 numbrit pikk. Kasutajal on oma tunnusnumber ja raamatukoguga liitumise kuupäev.

Laenutused: Kui kasutaja laenutab raamatu, siis salvestame, milline kasutaja ja milline raamat. Salvestame laenutuse kuupäeva ja tagastamise tähtaja (tähtaeg on alati 14 päeva pärast laenutamist). Kui raamat tagastatakse, märgime tagastamise kuupäeva. Ühte raamatut saab laenutada korraga ainult üks kasutaja.

Reeglid ja piirangud:

  • Igal kasutajal võib olla korraga laenutada kuni 5 raamatut
  • Raamatut ei saa laenutada, kui see on juba välja laenutatud
  • Kui raamat tagastatakse pärast tähtaega, arvestatakse trahvi 0.50 € iga hilinenud päeva eest
  • Kui laenutatud raamatut pole 14 päeva jooksul tagastatud saadetakse kasutajale meeldetuletus

Samm-sammult¶

1. Tuvasta klassid¶

Loe läbi nõuded ja mõtle, millised "asjad" seal esinevad. Iga selline "asi" on tõenäoliselt klass.

Vihje: otsi nimisõnu – raamat, kasutaja, laenutus…

2. Tuvasta omadused¶

Igal klassil on omadused. Näiteks raamatul on pealkiri, autor, ISBN jne.

Tee tabel iga klassi kohta:

Klass Omadus Tüüp Kohustuslik? Reeglid
Book Title string jah max 200 tähemärki
Book Author string jah max 100 tähemärki
Book ISBN string jah täpselt 13 tähemärki
Book YearPublished int jah >= 1900 ja <= praegune aasta
Book Pages int jah >= 1
Book IsAvailable bool jah vaikimisi true

Tähelepanu!

Klasside ja omaduste nimed on tavaliselt inglise keeles. Nime osad algavad C# korral suure tähega (YearPublished, IsAvailable). Nimed pane sellised, et need oleksid inimestele arusaadavad. Arusaadava koodiga on lihtsam töötada nii sinul, sinu kolleegidel kui ka - üllatus, üllatus - AI-l.

3. Tuvasta seosed¶

Kuidas klassid omavahel seotud on?

  • Raamat ja laenutus – ühte raamatut võib mitu korda laenutada (aga korraga ainult üks kord). Seos: üks raamat ➔ mitu laenutust
  • Kasutaja ja laenutus – üks kasutaja võib teha mitu laenutust (aga korraga kuni 5). Seos: üks kasutaja ➔ mitu laenutust

4. Vaata näidist¶

Allpool on klassiskeem, mis näitab, kuidas Raamatukogu süsteemi klassid omavahel seotud on. Sinu enda skeem peaks välja nägema umbes samasugune.

classDiagram
    class Book {
        Book
        Autor
        ISBN
        YearPublished
        Pages
        IsAvailable
    }

    class User {
        FirstName
        LastName
        Email
        Phone
        MembershipNo
        DateRegistered
    }

    class Borrowing {
        BorrowingDate
        ReturnDeadline
        ReturnDate
    }

    User "1" --> "0..5" Borrowing : teeb
    Book "1" --> "0..*" Borrowing : laenutatakse

Mida siin näed?

  • Iga kast on üks klass – sealt näed klassi nime ja tema omadusi
  • Nooled näitavad seoseid:
  • Kasutaja "1" --> "0..5" Laenutus – üks kasutaja võib teha 0 kuni 5 laenutust
  • Book "1" --> "0..*" Laenutus – ühte raamatut võib mitu korda laenutada

5. Tee klassiskeem diagrams.net¶

  1. Ava diagrams.net (enda arvutis või veebis, vali ise)
  2. Vali "Blank Diagram"
  3. Paremal pool paneelil otsi "UML" või "class"
  4. Lohista klassikujundid (class) töölauale
  5. Iga klassi kohta:
  6. Kirjuta üles klassi nimi
  7. Kirjuta omadused koos tüübiga (nt +pealkiri: string)
  8. Joonista seosed klasside vahele
  9. Lihtne joon (association) tähendab, et klassid on seotud
  10. Nool: klass A teab klassist B
  11. Märgi ka seose tüüp (1…* jne)

6. Dokumenteeri klassid¶

Iga klassi kohta kirjuta faili või tabelisse:

Klass: Book
Kirjeldus: Raamatut esindav klass
Omadused:
  - Title (string, kohustuslik, max 200 tähemärki)
  - Author (string, kohustuslik, max 100 tähemärki)
  - ISBN (string, kohustuslik, täpselt 13 tähemärki)
  - YearPublished (int, kohustuslik, >= 1900 ja <= praegune aasta)
  - Pages (int, kohustuslik, >= 1)
  - IsAvailable (bool, kohustuslik, vaikimisi true)
Seosed:
  - Laenutus: ühel raamatul võib olla mitu laenutust (1…*)

Klasside vahelised seosed koodis¶

Selle info põhjal saame nüüd luua klassid, kuid need näevad välja veidike teistsugused kui see, mis on toodud joonisel. Meil on klasside vahel seosed, mis programmi koodis lahendatakse omadustena (nende eriliste omaduste kohta öeldakse ka navigational property).

Note

Navigational property on selline klassi omadus, mis kasutab mõnda sellist tüüpi, mida me hoiame andmebaasis. Navigeerimine tähendab antud juhul siis infot kuidas liikuda ühe klassi pealt teisele.

public class Book
{
    // Tavalised omadused
    // ...    
}

public class User
{ 
    // Tavalised omadused
    // ...    
}

public class Borrowing
{
    // Tavalised omadused
    // ...

    // Navigeerimise omadused
    public Book Book { get; set; }
    public User User { get; set; }
}

See on kõige minimaalsem, mis on vajalik selleks, et kujutada ülal joonisel toodud seoseid.

Kindlasti kohtute elus ka sellise koodiga, kus on loendite kujul navigeerimise omadused kasutusel. Järgnevas näiteks on nii raamatule kui kasutajale lisatud laenutuste loend.

public class Book
{
    // Tavalised omadused
    // ...    

    // Navigeerimise omadused
    public IList<Borrowings> Borrowings { get; set; }
}

public class User
{ 
    // Tavalised omadused
    // ...

    // Navigeerimise omadused
    public IList<Borrowings> Borrowings { get; set; }
}

public class Borrowing
{
    // Tavalised omadused
    // ...

    // Navigeerimise omadused
    public Book Book { get; set; }
    public User User { get; set; }
}

Teadmiseks

On olemas erinevad professionaalsel tasemel modelleerimise programmid, mis oskavad klassiskeemide põhjal klasside koodi ise valmis kirjutada. Neid programme me lihtsamate süsteemide ehitamisel tavaliselt ei kasuta.

Kokkuvõte¶

  • Modelleerimine aitab sul enne koodi kirjutamist asjad läbi mõelda
  • Loe nõuded hoolikalt läbi ja otsi "asju" (klasse) ja nende andmeid (omadusi)
  • Igal omadusel on tüüp ja reeglid – pane need kirja
  • Hoia dokumentatsioon ja skeem kooskõlas
