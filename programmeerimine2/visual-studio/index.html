Visual Studio¶

Visual Studio on Microsofti arenduskeskkond (IDE – Integrated Development Environment). See on programm, kus me kirjutame koodi, ehitame rakendusi ja haldame oma koodi. Visual Studio toetab paljusid programmeerimiskeeli – meie kasutame .NET raamistikku ja C# programmeerimiskeelt.

.NET programme, mis otseselt Windowsi komponente ei vaja, saab ehitada ka Linuxi ja Macide peal. C# on keelena valitud seepärast, et selle oskamisel on lihtsam omandada sellised keeled nagu Java, PHP (objekt-orienteeritud osa) ja TypeScript. Kindlasti leidub veel keeli, mille kirjapilt on sarnane.

Projektid ja lahendused (solution)¶

Visual Studios struktureeritakse programmid selliselt. Lahendus ehk solution on konteiner, mis sisaldab ühte või mitut projekti. Lahenduse failil on laiend .sln või .slnx.

Programm või süsteem koosneb sageli mitmest osast:

  • Veebirakendus, mis pakub API-t (näiteks ASP.NET Core Web API)
  • Kasutusliidese projekt (näiteks Angular või Blazor)
  • Äriloogika teek (Class Library)
  • Mobiilirakendused
  • Testide projekt (Test Project)

Kõik need on eraldi projektid, aga nad kuuluvad ühte lahendusse.

Ülal joonisel on Web API projekti nimi paksus kirjas. See on seepärast, et tegemist on käivitusprojektiga (startup project). Kui me vajutame Visual Studios F5-klahvi, et programm käima lasta, siis käivitatakse just see projekt.

Lahendusega töötamine¶

Tegevus Kuidas teha
Uue lahenduse loomine File → New → Project → vali projekti tüüp ja anna lahendusele nimi
Olemasoleva lahenduse avamine File → Open → Project/Solution → vali .sln fail
Projekti lisamine lahendusse Paremklõps lahendusel Solution Exploreris → Add → New Project või Existing Project

Tip

Visual Studio loob uue projekti loomisel automaatselt ka lahenduse.

Projektid¶

Iga projekt (project) on eraldi programm või komponent. Igal projektil on oma .csproj fail (C# projekti puhul), mis sisaldab:

  • Projekti nime ja tüüpi
  • Viiteid kasutatavatele teekidele (dependencies)
  • Kompileerimise seadeid (.NET versioon, platvorm jne)

Levinumad projektitüübid on toodud järgnevas tabelis.

Tüüp Kirjeldus
Console App Lihtne konsoolirakendus, töötab käsureal
ASP.NET Core Web API Veebiteenus, mis vastab HTTP-päringutele
Windows Forms Desktop-rakendus Windowsile
WPF Kaasaegsem desktop-rakendus Windowsile
Class Library Teek, mida saavad kasutada teised projektid
xUnit Test Project Testide projekt xUnit raamistikuga
MSTest Test Project Testide projekt MS Test raamistikuga

Projekti struktuur Solution Exploreris¶

HelloWorld (projekt)
├── Dependencies
│   ├── Analyzers
│   ├── Frameworks
│   └── Packages (NuGet)
├── Program.cs
└── HelloWorld.csproj

Projekti sõltuvuste haldamine¶

Projektide sõltuvused (öeldakse ka seosed, inglise keelne termin on dependency) jagunevad kolmeks:

  1. Frameworks – süsteemi teegid (.NET runtime ise)
  2. Packages – paketihalduri kaudu lisatud paketid (kolmandate osapoolte teegid)
  3. Project References – viited teistele projektidele samas lahenduses

Projektide vahelisi viiteid saab lisada: paremklõps Dependencies peal → Add Project Reference.

Projekt, mis viitab teisele projektile, saab kasutada selles olevaid klasse ja muid elemente.

NuGet paketihaldur¶

NuGet on .NET-i paketihaldur. NuGet võimaldab lisada oma projekti valmis teeke, mida teised arendajad on loonud.

Miks NuGeti kasutada?

  • ära kirjuta ise seda, mis on juba olemas
  • suur kogukond – tuhanded tasuta teegid
  • lihtne uuendada – ühe klikiga uus versioon
  • TURVALISUS – NuGet kontrollib pakette ja nende allkirju

Paketihalduri kasutamine Visual Studios on lihtne:

  1. Paremklõpsa projektil Solution Exploreris → Manage NuGet Packages
  2. Browse vahekaardil otsi vajalikku paketti (näiteks Dapper või Newtonsoft.Json)
  3. Vali pakett ja vajuta Install

Paketihalduri abil on võimalik ka pakette uuendada ja eemaldada. Pakettide haldus on võimalik ka lahenduse tasemel. Lahenduse tasemel saame pakette konsolideerida - garanteerida, et kõik projektid kasutavad pakettide samu versioone. Sel teel hoiame ära versioonide konfliktid.

Paketi haldurit saab kasutada ka Visual Studiost paketihalduri konsooli kaudu ja käsurealt. Samuti on võimalik pakettide viiteid lisada otse projektifaili (enamasti seda vaja pole).

Tähelepanu!

Veendu alati, et kasutad paketi uusimat stabiilset versiooni. Ära installi beetaversioone õppetöös.

Git Visual Studios¶

Visual Studios on Git täielikult integreeritud – sa ei pea tingimata Giti käsurealt kasutama (aga seda tuleb siiski osata). On vahendid koodihoidla vaatamiseks ja muudatuste haldamiseks. Samuti on olemas kõik vajalik uute harude ja PR-ide loomiseks jne.

Git Repository aken¶

Ava: View → Git Repository. See aken näitab käesoleva haru muudatuste ajalugu. Kõik Giti serverisse jõudnud commitid on siin näha. Commiti peal klikkides näeme ka muutunud faile ja saame ridade kaupa võrrelda, et mis täpselt muutus.

Tähelepanu!

Vaata joonisel commitite ajalugu. Siit joonistub kenasti välja miks peavad commitite selgitused olema lakoonilised ja arusaadavad. Kujutle vaimusilmas korra ette, et arusaadavate kommentaaride asemel on kommentaarid stiilis "22.10.2025", "Update", "Update again", "Fix", "Commit". Kas sellise versioonide ajaloo korral oleks lihtne leida üles mõni konkreetne huvipakkuv commit?

Git Changes aken¶

Teine oluline aken on Git Changes. See aken näitab meile muudatusi, mille oleme teinud peale viimast commitit. Muudatus võib olla lisaks mõne faili muutmisele ka failide lisamine ja kustutamine.

Selle akna kaudu saab teha commiti ja lükata muudatused Giti serverisse. Samuti on võimalik muutunud faile võrrelda vastu eelmist seisu, et näha ära, mis täpselt muutus.
